# Structurizr Template

**Генерация архитектуры Structurizr с помощью AI-агентов**

Репозиторий содержит инструкции, навыки и настройки, которые помогают AI-агентам преобразовать описание архитектуры системы в валидный Structurizr DSL и диаграммы Mermaid.

## Основной сценарий

1. Передайте агенту документ с описанием архитектуры или вставьте текст.
2. Агент извлечёт из источника архитектурные факты, составит перечень систем, контейнеров и связей, затем создаст `./structurizr/workspace.dsl`.
3. Отдельный reviewer сверит DSL с исходными материалами. Оркестратор внесёт подтверждённые исправления и проверит DSL через Structurizr MCP.
4. Для каждого представления Structurizr агент сохранит исходный Mermaid в отдельный файл `./structurizr/<ключ-представления>.mmd`.

Промпт для запуска: **«Создай Structurizr workspace и Mermaid-диаграммы по этим материалам».**

PDF поддерживается, включая длинные документы, но если есть выбор, предпочтительнее легко читаемый текстовый формат: Markdown, обычный текст, DOCX или документ Google Drive, к которому у агента подключён доступ. PDF-навык используется только для PDF; для остальных источников есть отдельный навык извлечения. Промежуточные выдержки, OCR и отчёт reviewer хранятся в контексте агента, а не в файлах репозитория.

## Возможности репозитория

- Извлечение архитектурных сведений из PDF, Markdown, текста, DOCX и доступных документов Google Drive с указанием страниц или разделов источника.
- Создание `workspace.dsl` и представлений контекста системы и контейнеров. Контейнерные диаграммы — главный результат; component- и code-диаграммы запрещены.
- Независимая проверка модели reviewer-агентом и исправление замечаний оркестратором.
- Проверка DSL и экспорт всех представлений в Mermaid через Structurizr MCP.
- Сохранение Mermaid как отдельных `.mmd` файлов без Markdown-обёртки.
- Запуск локального сайта Structurizr в Docker на `http://localhost:5555`.
- Экспорт диаграмм в PNG или SVG с помощью Docker-образа `structurizr/structurizr:2026.10.26-playwright`.
- Публикация статического сайта через настроенный GitHub Pages workflow.
- Работа с Codex и Claude Code; инструкции и навыки находятся в репозитории. Для других агентных инструментов можно использовать тот же репозиторий и MCP-конфигурацию, если клиент поддерживает `AGENTS.md`, навыки или позволяет передать эти инструкции вручную. Репозиторий не привязан к конкретной IDE или текстовому редактору.

Проектные ограничения и порядок работы описаны в [`AGENTS.md`](AGENTS.md). Навыки PDF, других источников, генерации DSL, локального сайта и экспорта PNG/SVG находятся в `.agents/skills/`. Mermaid-диаграммы и DSL размещаются в `./structurizr/`.

## Просмотр Mermaid в VS Code

Для предпросмотра `.mmd` файлов очень рекомендуется расширение [`vstirbu.vscode-mermaid-preview`](https://marketplace.visualstudio.com/items?itemName=vstirbu.vscode-mermaid-preview). Откройте `.mmd` файл, нажмите **Ctrl+Shift+P** и выберите **Mermaid Preview: Preview Diagram**.

VS Code рекомендуется для удобного предпросмотра, но не обязателен: можно использовать любую IDE или текстовый редактор. Репозиторий и агентный workflow не требуют конкретного редактора.

## Локальный сайт и изображения

Навыки Docker запускают локальный Structurizr или экспортируют представления в PNG/SVG по запросу. Источник для команд Docker — `./structurizr/workspace.dsl`; команды монтируют папку `./structurizr` в контейнер. Инструкции по диагностике ошибок прав доступа находятся в соответствующих навыках.

Для примеров возможностей Structurizr — представлений, стилей и других настроек DSL — смотрите репозиторий [`structurizr-adept/structurizr-example`](https://github.com/structurizr-adept/structurizr-example).

## GitHub Pages

В `.github/workflows/deploy.yml` настроена сборка статического сайта Structurizr и публикация через GitHub Pages. Чтобы workflow собрал именно ваш workspace, файл `./structurizr/workspace.dsl` должен быть добавлен в репозиторий, закоммичен и запушен в GitHub. Автоматический запуск настроен на push в ветку `master`, когда меняется `structurizr/workspace.dsl` или сам workflow; также доступен ручной запуск через `workflow_dispatch`. В настройках репозитория GitHub Pages должен быть выбран источник публикации **GitHub Actions**.

## Архитектурные правила

- Основной уровень — контейнеры; system context добавляется, когда он помогает показать людей и внешние системы.
- Component-, code-, deployment- и dynamic-представления не создаются.
- Модель содержит только факты, подтверждённые исходными материалами; неизвестные протоколы и технологии не додумываются.
- Если исходный документ на русском языке, человекочитаемые названия и описания в DSL также пишутся на русском, сохраняя официальные названия продуктов и протоколов.
- ADR-файлы и промежуточные артефакты не создаются.
